## Material validation gap

Specification Section 15 requires matching state identities, token causality, and actual online gate decisions. The current `validate()` checks a subset. Its existing eight tests pass. The separate [CPU fixture](../tests/test_contract_validator_scope_v1.py) preserves three accepted inputs that lack a required semantic witness:

1. An unregistered `history:q_OTHER...` read passes because the key starts with `history:`.
2. A future decode token has no sampled-token producer or registered prior completion.
3. A continuation depends only on another request's gate, despite matching token position and preceding depth.

All three return true from the existing checker. The fixture records expected semantic legality as false. Its five characterization tests pass. These tests expose coverage limits. They do not show that any previously generated graph is invalid.

The graph generator and candidate-specific tests can supply stronger constraints than this generic function. The audit does not erase those tests. However, a `DAG_CHECKS_PASS` label alone cannot certify every Section 15 obligation. Historical version registration, token availability, gate identity/policy, resource leases, and communication contention need explicit coverage before a survivor relies on them.

No validator fix occurs here. The coordinator will decide its scope after reviewing these counterexamples.
