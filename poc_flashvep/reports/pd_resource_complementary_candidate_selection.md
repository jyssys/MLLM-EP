# Physical candidate selection

The screen requires a real model tensor path, actual GPU execution and data movement where the dependency crosses GPUs, valid numerical probes, decode protection, and a credible ≥10% gain against the applicable generic mechanism. Prior work and historical measurements are separate controls. No A–D branch satisfied the advance gate. The online phase therefore measures native and generic controls and keeps proposed-candidate serving marked `NOT_RUN`.

| Screen | A — Operator-level | B — Destination-aware | C — MoE sharing | D — Heterogeneous prefill |
|---|---|---|---|---|
| Motivation | Dense native P backlog, little D Tensor activity, FA3/MLP resource asymmetry in a real block | Physical NIXL read of 144 GiB for 64 × 16K, many per-transfer descriptors | Expert-sharded P/D geometry and physical all-to-all on H200 | Different communication and workload balance for attention and MLP |

| Verdict | `NO_GO_INTERFERENCE` | `NO_GO_COMMUNICATION` | `NO_GO_INCREMENTAL` | `NO_GO_INCREMENTAL` |

Spatial A measured 40 physical cells and found no layout with both healthy D and a competitive P MLP at the target geometries. This removes resource mismeasurement as the sole explanation for the ordinary-stream result. A and B cannot add their respective gains for the same MLP boundary because the destination still needs the already computed K/V. The half-share MLP row trial proves useful work completed, but its best decode-compatible schedules consumed a temporal opportunity that can also admit coarse whole requests.

Study priority after this screen is the strongest generic PD allocation and handoff. If a future workload has a qualitatively different overlap opportunity, measure an observed deadline-safe period first, then retest a transfer-complete operator candidate against native request routing on the same GPU budget. POD-Attention, published elastic runtime artifacts and new production hybrid integration were not executed.
