# EPD Prefill-heavy 및 Modality-aware Deflection 선행연구

2026-11-28 기준으로 프로젝트의 고정 Git revision, 논문의 방법·실험 절, 접근 가능한 공개 구현을 대조했다. 아래 H100·H200 수치는 각각 이전 실험의 증거다. 아티팩트 열의 `UNVERIFIED`는 논문에 명시된 동작의 공개 구현을 확인하지 못했다는 뜻이다. 전제하는 실행 구성은 BF16 Dense MLLM의 물리적 1E/1P/1D, 실제 이미지 입력, 요청 간 캐시 재사용 비활성화다.

## 일곱 가지 선행연구 질문에 대한 판정

1. **MLLM EPD에서도 P-heavy/D-idle를 다룬 선행이 있는가?** 공개 EPD의 stage imbalance 및 D→P elasticity, 프로젝트의 H100/H200 MLLM 동시 trace·offload 연구가 있다. 기존 H200 grid의 qualified lower-D 조건과 같은 시각의 모든 M1/M2 조건은 통과하지 못했다.
2. **D GPU가 LM Prefill을 실행한 선행이 있는가?** ICML EPD의 역할 전환, UnifiedServe의 논리 stage 공유, 프로젝트의 물리 H100 E→D whole-request가 각각 존재한다. 이번 Native 1E/1P/1D에서 실행 가능한 새 요청의 추가 서비스를 별도로 계측한다.
3. **E GPU가 바쁠 때 E-side assistance의 한계를 조사했는가?** EAServe가 E/P 병목과 공유를 분석했고 EADA가 vision/remote attention 간섭을 실측했다. 일치시킨 LM Prefill workload의 E-local vs D-local intervention은 확인한 선행에서 미검증이다.
4. **Kairos/FluidPD의 Multimodal 적용 선행이 있는가?** 두 원문에서 E를 분리한 실험은 확인하지 못했다. 프로젝트에 이미 각각의 generic 계열과 직접 비교되는 whole-request 및 token split 실행이 있다.
5. **P/D 이미지 경계 분할 선행이 있는가?** 프로젝트가 hard/inner cut, 실제 slice 이동, 동일 KV와 batch invariance를 검증했다. 현재 vLLM의 optional multimodal item chunk guard도 운영 대조로 포함할 수 있다.
6. **Visual Embedding readiness로 routing을 할 수 있는가?** 프로젝트 H100 proxy는 실제 E 완료 후 일괄 readiness로 P/D를 선택했다. RServe 계열의 공개 코드에서 일부 embedding readiness가 합법적인 causal prefix 실행을 제어한다.
7. **E→P pipeline과 E→D deflection을 함께 다루었는가?** 같은 1E/1P/1D에서 aggregate E-ready 경로를 고르는 프로젝트 코드가 있다. 이 감사 범위에서 확인되지 않은 좁은 지점은 **실제 per-item readiness 및 causal-prefix frontier로 P와 D의 요청별 배치를 개선하는 실행 정책**이다.

## 새 가설의 검증 단위

- **Motivation.** H200에서 같은 중앙 observation window로 실제 P compute-ready backlog, P/D throughput, Decode admission 및 absolute SLO와 kernel union을 증명한다. E 높은 이용률의 추가 증거는 E/P/D 실제 교집합과 E-only 근접도로 기록한다. 기존 H200의 E/P 고부하와 D의 55.82% diagnostic busy는 비교점이다.
- **Generic 기준선.** 동일 E와 실제 LM-ready embedding를 사용하는 1E/1P/1D, 전체 E 완료 이후 whole-request, 관측된 length/cost·KV·deadline으로 계산하는 Kairos-style 정책, D-local chunk sweep을 비교한다. Stock inline NativeStrong과 동일 transport 정책의 native A/B는 구분한다.
- **Readiness 가설.** 실제 image-ready timestamp가 있으면 일반적인 request-completion 기반과 같은 causal prefix를 P에서 일찍 실행하는 대조를 먼저 둔다. 각 비교에 같은 E batching을 적용하고 총 token 수, 도착한 Embedding bytes 및 KV 비용을 공통 입력으로 제공한다. 이어서 같은 arrival trace로 일반 LM에 재생한다. D로 일찍 보낼 시 이미 만든 prefix KV, image 순서와 MRoPE, 페이지 소유권 및 실제 Decode deadline을 유지할 수 있는지 확인한다. 후속 image 도착을 미래 정보 없이 처리할 수 있다는 근거가 필요하다.
- **경계 및 표현 검증.** legal boundary, hash로 고른 random legal boundary, actual token/time 비용 기준 cut에 동일한 slice transport를 적용한다. MRoPE와 processor geometry를 보존한 상태에서 실측 scheduling quantum·tensor lifetime·bytes가 달라야 modality 기여를 주장할 수 있다. Full KV 대비 작은 embedding의 전송 절약은 E→D에 실제 들어간 비용과 Text-only deflection에서 절약한 KV를 포함해 분해한다.
- **판정 범위.** per-item signal의 trace 상관관계나 offline oracle만 확보하면 N0는 미통과다. Runtime에서 요청 일괄 완료만 관측되면 per-image 신호를 `NOT_RUN`으로 남긴다. Whole-request가 성공하면 `GENERIC_DEFLECTION_ONLY` 범위에서 판정하며, 동일 강한 기준선 이후의 추가 이득이 확인될 때 modality-specific 후보로 확장한다.
