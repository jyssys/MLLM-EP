## Concrete novelty tests

1. **Selected P operators on D.** OpScale schedules operator classes. DuetServe and Nexus provide spatial phase multiplexing. FlashInfer POD fuses two attention paths. ConfluxServe shares linear GEMMs and preserves phase-specific attention within a serving batch. In these reviewed dense sharing paths, D's execution of a selected P-side MLP row group followed by activation return to the originating P residual stream remains a distinct experiment. For Qwen3-8B BF16, the minimum payload for complete hidden rows is two directions × 4,096 values × 2 B = 16,384 B per row, per remote MLP boundary. This is an `ANALYTICAL_BOUND` and excludes metadata, packing, synchronization and contention. The same row group needs a deadline-safe GPU quantum and an observed net critical-path improvement relative to full request, token, layer and mixed-GEMM controls. [Qwen3-8B configuration](https://huggingface.co/Qwen/Qwen3-8B/blob/b968826d9c46dd6066d109eabc6255188de91218/config.json), [OpScale](https://arxiv.org/html/2608.13499v1), [ConfluxServe](https://arxiv.org/html/2610.37810v1), [DuetServe](https://proceedings.mlr.press/v306/gao26m.html)
2. **Decode attention with P MLP on one GPU.** The reviewed fused POD implementation pairs attention with attention. Mixed-phase serving already executes both phase workloads on shared hardware, and DuetServe and Nexus address spatial overlap. A comparison should condition on actual D attention geometry and use isolated, sequential, ordinary stream, priority and supported spatial placements. Remote P MLP is feasible only if its complete P→D→P path and P's dependency wait fit the measured savings. Record SM and HBM counters before attributing any wall-time overlap to resource complementarity. [FlashInfer implementation](https://github.com/flashinfer-ai/flashinfer/blob/main/flashinfer/pod.py), [DuetServe](https://proceedings.mlr.press/v306/gao26m.html), [Nexus](https://arxiv.org/html/2507.06608v1)
3. **Token offloading and replicated weights.** FluidToken admits a suffix using predicted D slack and FluidRole retains weights through role changes. The historical exact layer/token studies establish geometry-dependent outcomes. Holding GPU count, model residency, attention backend and actual prefill rows fixed isolates what operator-level work adds. CUDA priority can affect queued work. Measure delay from an already-running GEMM separately. [FluidPD](https://arxiv.org/html/2610.06917v1), [CUDA stream priorities](https://docs.nvidia.com/cuda/cuda-runtime-api/group__CUDART__STREAM.html)
4. **Consumer-local KV and reconstruction.** On Qwen3-8B, hidden state is 8,192 B/token and one layer's K+V is 4,096 B/token at BF16 with eight KV heads and head dimension 128. A per-layer hidden transfer therefore doubles the raw payload and leaves P's own attention projection intact. A single common boundary state can reduce bytes across three or more suffix layers, conditional on the exact suffix execution and duplication cost. ReKV already implements this construction in PD. A new B contribution requires a different measured dependency or scheduling gain, such as generating truly D-owned KV while doing already-beneficial remote work and without repeated projection. Many activation-only operators have no direct relation to the same layer's K/V. [Qwen3-8B configuration](https://huggingface.co/Qwen/Qwen3-8B/blob/b968826d9c46dd6066d109eabc6255188de91218/config.json), [ReKV](https://arxiv.org/html/2611.08770v1), [Kairos](https://arxiv.org/abs/2607.02043)
5. **Cross-phase Expert work.** ExpertPlex establishes a prior baseline for pooled experts and tile-priority P/D work already. Weave and DeepEP establish communication/compute partitioning inside MoE. Any new C candidate must exercise physical dispatch and combine under the actual expert placement and show a scheduling or placement advantage over this overlap. Reusing identical ownership across P/D ranks is an explicit assumption to validate, along with prefill and decode route distributions. [ExpertPlex](https://arxiv.org/html/2607.18002v1), [Weave](https://arxiv.org/abs/2611.27765), [DeepEP source](https://github.com/deepseek-ai/DeepEP)
6. **Operator-specific P layout plus PD handoff.** Ulysses and ring/Ulysses hybrids cover Attention-specific partitioning with conversion. DistServe tunes per-phase resource allocation. ConfluxServe already pipelines a transfer from head-sharded P to rank-local D and aliases page views within a shared pool. The open proof for D is an equal-P-budget execution in which the chosen P layout both speeds the prefilling critical path and saves conversion or transfer into D's actual paged KV layout. Keep D fixed and charge transposes, all-to-all, collectives and D admission. [Ulysses](https://arxiv.org/abs/2309.14509), [Unified SP](https://arxiv.org/abs/2405.07719), [DistServe](https://www.usenix.org/conference/osdi24/presentation/zhong-yinmin), [ConfluxServe](https://arxiv.org/html/2610.37810v1)

A retains a narrow incremental question after the audit. B's proposed contiguous suffix construction and C's shared expert service have close direct precedent. D needs a layout or handoff advantage beyond selecting a prefill CP strategy and the ConfluxServe path. These are source audit judgments. Campaign verdicts are tied to the physical and online gates in the experiment specification.
