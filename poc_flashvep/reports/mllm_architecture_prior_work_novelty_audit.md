# Architecture-first disaggregation novelty audit

Architecture-first disaggregation starts from executable module reachability and tensor dependency at a checkpoint, request type and serving phase. The research opportunity is a measurable advantage against the strongest same-model placement for that graph. The scope below covers exact image→text inference. Approximate token removal, learned rerouting, image generation, and simulated scheduling each carry different evidence.

## Two primary candidate claims

| Question | CogVLM2 visual decoder bank | IDEFICS visual cross memory |
| --- | --- | --- |
| **Would generic AR use the mechanism?** | Any hard conditional AR graph can exclude a bank proven unreachable on a role. The concrete differentiator is a native, deterministically modality-selected expert bank in each LLM layer, with a measurable P→D change in reachability. | Encoder-decoder AR and some multimodal fusion networks have fixed cross-attention memory. IDEFICS provides a concrete, interleaved image-conditioned implementation and dedicated gated cross weights. |
| **How does it extend EPD?** | Ordinary EPD moves the vision encoder to E and the language model to P/D. This variant may also load only the D-reachable language branch within that language model, after P generated its KV using the full checkpoint. | E produces the visual representation as before. A separate visual cross role would also own its K/V and/or weights while language prefill and generation issue requests. The decoder's self-KV remains an independent state path. |
| **Do TP/PP/CP/EP cover it?** | Generic TP and PP can distribute resident weights, and EP can place token-routed experts. The control is the same-model configured dense language graph plus a same-budget generic placement, with proof of loaded tensors. Ordinary prefill/decode throughput cannot prove bank removal. | DCP and Flash-Decoding cover the exact mathematical merge and generic K/V placement. Operator or pipeline parallelism can already place the cross module separately. The concrete question is whether fixed visual-only reuse yields enough saved memory or useful concurrency to repay recurring communication. |
| **What dependency could be new in the serving result?** | A D weight-residency closure from actual stock token-mask and boundary reachability, with exact handoff and output parity. Check multi-image/text boundaries, both QKV and FFN masks, first emission, continuation and any dummy branch. Demonstrate direct memory or capacity effect without changing model, semantics, engine batch or allowed GPU count. | A measured deployment crossover for fixed vision K/V and dedicated cross blocks, with visual-state ownership, path frequency and Q/partial-result traffic measured. Directly compare a local cross baseline, matched in-process control and a generic same-size K/V/operator placement. |
| **What generalizes?** | Audit reachable modules before assigning DP, TP or EPD roles. Different models can have shared, hard-exclusive or soft-routed execution. Capacity benefit depends on a large enough unreachable bank and the achievable batched D workload. | Place immutable conditioning state according to its production phase, consumer frequency, weight residency and interconnect. This is useful to AR with external memory and does not generalize from image labels alone. |

A dormant checkpoint bank and mathematical zero are distinct. For example, XComposer's all-text PLoRA reference invokes one adapter row and adds zero. Omission needs an exact check in the selected numeric regime. BAGEL's established text-scope vLLM initializes the understanding stack and skips generation-specific weights. A full-checkpoint load is an informative structural reference. The production comparison for BAGEL is the existing text-scope path. [PLoRA code](https://huggingface.co/internlm/internlm-xcomposer2-4khd-7b/resolve/a2c222ebd3a723c3dff00232e4f5cc6429f472d1/build_mlp.py) · [BAGEL author source](https://github.com/ByteDance-Seed/Bagel/blob/a2fa77dd8caeefc41e6607ae0ec17408d3f4ee9f/inferencer.py) · [vLLM BAGEL load mapping](https://github.com/vllm-project/vllm/blob/main/vllm/model_executor/models/bagel.py)

ERNIE strengthens the generality test for the CogVLM2 hypothesis. Both can retain modality-conditioned prompt history in K/V when generated rows stop using the visual FFNs. Cog also selects modality-specific QKV and output projections, while ERNIE retains one QKV/O set for both modalities and chooses top-6 experts inside the selected bank. The source-derived ERNIE visual-router and expert payload is 13,607,239,680 bytes before engine allocation effects. That is a candidate residency reduction, whereas native execution already skips the visual kernels on text-only steps. Attention over visual prompt K/V remains. EP can distribute both banks across ranks, and generic conditional AR can apply the same reachability argument. The untested question is whether omission at the EPD D role pays off over native EP, TP or ordinary full-bank D with the same budget and exact serving contract. [Source accounting](../mllm_architecture_first_disaggregation_discovery/results/candidate_source_metadata.json) · [ERNIE native mask and loading](https://github.com/vllm-project/vllm/blob/main/vllm/model_executor/models/ernie45_vl.py)

OCR2 offers a dependency that two same-size arbitrary token partitions cannot infer from their sizes alone. Image-prefix queries cannot read the learned flow queries in the published block mask, whereas flow queries can read the image state. That is an exact graph cut candidate inside E. Parallel or staged execution and KV materialization are standard techniques. A useful result would quantify native end-to-end savings with the original asymmetric mask, preserving the layer-wise interface and reducing stages or resource cost at matched input geometry. [OCR2 mask and query code](https://huggingface.co/deepseek-ai/DeepSeek-OCR-2/blob/aaa02f3811945a91062062994c5c4a3f4c0af2b0/deepencoderv2.py)

## Falsifiable evidence requirements

- **Graph.** Confirm exact checkpoint source, reachable modules and both phase-specific state sets for actual requests. Static code reachability identifies a candidate. Native invocation counts determine whether that path is exercised and by how many rows.
- **Semantics.** Match native image shapes, token order, attention masks, positions, original checkpoints and dtype. Compare logits, greedy token sequences and prefill-to-decode continuation under the same actual geometry. Changing masks, expert routing or quantization is a separate intervention.
- **Resources.** Record active and physically loaded weights separately from allocated and resident KV. Measure per-GPU peaks, initial transfers, recurrent transfer latency and decode throughput. Include the same-shape and same-GPU-budget generic baseline and the strongest stock or appropriately scoped existing one.
- **Serving.** Apply the user's staged gates to real queueing, same arrivals and same supported roster before inferring TTFT, ITL, TPOT or goodput gains. Preserve output length and quality, and use independent starts when claiming reproducibility. Report input eligibility across Discovery and Validation.

## Prior local results and boundary of the claim

The preceding Qwen2.5-VL Discovery200 campaign found a real modality-by-layer effect without a new independently profitable placement. Generic two-GPU splitting improved isolated long inputs, while matching the image boundary added at most 2.0% latency reduction and 0.4% working-allocation improvement over the generic split on that tested scope. Its Full28 visual K/V route matched greedy output on its tested cases but cost about 5.36–5.47 ms more per eager decode step. At ragged B4, local, visual partition and generic-prefix attention paths were 12.860, 18.328 and 18.305 ms/step. Thus a visual label and exact reduction alone were insufficient in that architecture. The current study changes the checkpoint graph and asks whether a hard expert route or separate cross module changes that conclusion on measured configurations. [Earlier Qwen outcome](mllm_specific_disaggregation_discovery_final_summary.md) · [Qwen break-even evidence](mllm_visual_memory_remote_attention_break_even.md)

The defensible claim expands from exact mechanism evidence to an architecture-specific capacity or serving result only if those comparisons pass. A broader design principle requires replications across more than one qualifying family and evidence of the costs in cases that fail.
