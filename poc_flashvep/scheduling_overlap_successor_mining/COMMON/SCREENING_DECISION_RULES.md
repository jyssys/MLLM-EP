# Decision rules for closing the comparable screen

All three systems receive paper/code audit, supported native smoke, correctness
sanity, mechanism measurement, explicit MoE/MLLM transfer diagnostic, existing
option attack, labelled oracle and prior-art screen before any ranking. A
diagnostic does not silently satisfy the stronger native-port milestone.

## What the scores mean

Use the user's ten 0–5 dimensions: baseline fidelity, material failure severity,
direct request E2E headroom, feasible successor headroom, MoE/MLLM causality,
novelty, non-triviality, code feasibility, introduction strength and evidence.
The total is /50. A zero evidence/headroom score means **not established** where
the measurement is missing; it is not a numerical proof of zero universal
headroom. Scores cannot override a failed correctness or direct-request gate.

Choose exactly one screening leader by evidence and testability. That label is
not an automatic research promotion. If no candidate passes materiality and
non-triviality, record `FINALIST=NONE`, rather than inventing an MLLM failure,
running Kimi without the gate, or implementing an unjustified successor.

## Separate conclusions

- Low additional finite-policy/plan headroom closes **that measured selection
  space**, not all legal schedules. Untested portfolios are not bounded by it.
- A true request oracle must include admission, overlap and dependent work.
  Stage balance and resident-kernel overlap cannot be used in its place.
- A native path missing VL/EP/search semantics is a **port boundary**. It is not
  evidence the paper method fails. `PARTIAL_ENVIRONMENT_BLOCKED` may describe
  overall incomplete native-transfer coverage, with the exact missing code and
  successful alternate diagnostics named. It must not suggest all engines failed.
- `ALL_THREE_NO_GO` requires sufficient evidence for all three research claims;
  do not use it solely because manually chosen plans lose or full ports are
  absent. `FOUND_INCREMENTAL_ONLY` requires an actual incremental result, not
  merely successful reproduction of the original method.
- No new successor can be `FOUND_SUCCESSOR_STRONG_GO` without material direct
  request/SLO effect, causal non-trivial residual, independent repetitions,
  Kimi validation and a minimal prototype moving the frontier.

## Bias controls

All slow runs are retained unless an explicit runtime/correctness failure
invalidates them. Near-tie numerical disagreement triggers diagnosis but does
not authorize accepting a favorable mismatching pair. Small-n bootstrap intervals
resample whole restart pairs; request rows in one engine are not independent
restarts. A strong original-paper gain against a weak default is never credited
as the successor's additional gain.
