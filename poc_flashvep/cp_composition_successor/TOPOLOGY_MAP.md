# Topology map

## Physical safety scope

All live runs are restricted to `CUDA_VISIBLE_DEVICES=4,5,6,7`. Logical CUDA ranks 0--3 map to physical GPUs 4--7.

## Qwen3-VL primary checkpoint

- TP1/2/4, DCP1, PCP1: valid non-CP serving baselines.
- DCP2/4: invalid on four GPUs because Qwen3-VL has four KV heads and current GQA validation requires TP strictly greater than KV-head count.
- PCP2/4: current main PCP is MLA-only and explicitly rejects multimodal inputs.
- Consequence: no faithful Qwen3-VL native Track A/B/C CP experiment exists on this four-GPU fleet. Synthetic collectives will not be represented as production CP.

## DeepSeek-V2-Lite-Chat MLA MoE fallback

Candidate fixed-fleet topologies, EP disabled:

- CP1: DP4 × TP1 × PCP1 × DCP1.
- PCP2: DP2 × TP1 × PCP2 × DCP1.
- PCP4: DP1 × TP1 × PCP4 × DCP1.
- DCP2: DP2 × TP2 × DCP2 (or backend-valid equivalent).
- DCP4: DP1 × TP4 × DCP4.
- PCP+DCP: only current-validator- and backend-admitted factorizations; no assertion bypass.

The exact accepted matrix was generated by the measured v0.26 runtime. A source-admitted topology is not counted as supported until engine initialization and correctness both pass.

## Measured mapping

- Track A vanilla/spec: TP4 × PCP1 × DCP1, EP off.
- Track A DCP/combined: TP4 × PCP1 × DCP4, EP off.
- Track B PCP-only: TP1 × PCP4 × DCP1, EP off.
- Track B DCP-only: TP4 × PCP1 × DCP4, EP off.
- Track B combined: TP1 × PCP4 × DCP4 was validator-admitted but stalled in warmup in v0.26.
- Track C PCP1: four independent TP1/PCP1 replicas.
- Track C PCP2: two independent TP1/PCP2 replicas.
- Track C PCP4: one TP1/PCP4 replica.

Current CUDA PCP rejects managed DP greater than one, so Track C uses disjoint independent serving replicas while retaining `CUDA_VISIBLE_DEVICES=4,5,6,7` in every process. This is a fixed-fleet deployment comparison, not an emulated collective.
